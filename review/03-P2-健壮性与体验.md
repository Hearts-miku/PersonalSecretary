## 🆕 N-19 `CryptoManager` 在异常路径上 fail-open

**位置**：[CryptoManager.kt](https://github.com/Hearts-miku/PersonalSecretary/blob/2589cdd/app/src/main/java/com/example/data/local/CryptoManager.kt)
**置信度**：代码路径确定；触发概率需实机验证

本轮的加密实现（Android Keystore + AES-256-GCM）整体是对的，但两条异常路径都选择了
「继续可用」而非「明确失败」：

**其一，加密失败静默降级。** `encode` 在 `getOrCreateSecretKey()` 返回 null 或 Cipher
抛异常时，退回 Base64 的 `v1:` 格式：

```kotlin
} catch (e: Exception) {
    // 加密异常时退回 v1 格式保障可用性
}
// 降级兜底方案
val encoded = Base64.encodeToString(...)
return "$PREFIX_V1$encoded"
```

用户不会知道自己的 API Key 实际上没有被加密。

**其二，解密失败返回密文本身。** `v2:` 字符串解密失败时会穿过全部分支，落到最后一行：

```kotlin
// 无前缀纯文本直接返回兼容
return encodedText          // ← 此时是 "v2:AbCdEf..." 整串
```

这串密文随后会被当作 API Key 发进请求头。用户在设置页看到的也是这串乱码，无从判断
发生了什么。

设备上触发概率低——密钥未绑定用户认证（不会因锁屏变更失效），数据库也已排除在备份外
（不存在跨设备恢复导致密钥缺失的场景）。但 Keystore 瞬时异常在部分 ROM 上确有发生。

**建议**：解密失败返回空字符串，让上层走已有的「未配置 API Key」提示路径；
加密降级时至少记录日志，或在设置页给出提示。

## 🆕 N-20 API Key 被解密两次

**位置**：[WorkLogRepository.kt:33,44](https://github.com/Hearts-miku/PersonalSecretary/blob/2589cdd/app/src/main/java/com/example/data/repository/WorkLogRepository.kt#L33)、
[AiRepository.kt:32](https://github.com/Hearts-miku/PersonalSecretary/blob/2589cdd/app/src/main/java/com/example/data/ai/AiRepository.kt#L32)

```kotlin
// WorkLogRepository.getSettings()
s.copy(apiKey = CryptoManager.decode(s.apiKey))

// AiRepository.getEffectiveApiKey() —— 拿到的已是明文，又解一次
return CryptoManager.decode(rawKey).trim()
```

第二次解密作用在已是明文的值上，走「无前缀原样返回」分支，**功能上无害**。

但 encode / decode 的归属层次因此变得不清晰：两层都在做，读代码时无法判断某个
`UserSettingsEntity` 手里的 `apiKey` 是密文还是明文。建议明确由 `WorkLogRepository`
单独负责编解码，`AiRepository` 只接收明文。

## P2-13 文件导入无类型与大小限制

**位置**：[ProfileScreen.kt:213,298](https://github.com/Hearts-miku/PersonalSecretary/blob/2589cdd/app/src/main/java/com/example/ui/screens/ProfileScreen.kt#L213)

`filePickerLauncher.launch("*/*")` 接受任意类型文件并整体读入内存。UI 文案写
「导入 txt/md 文件」但 MIME 过滤没有对应。AI 提炼路径会把导入内容送进 prompt
（`sanitizeUserInput` 的长度截断兜了一层，但读文件这步的 OOM 风险仍在）。

**建议**：`launch(arrayOf("text/plain", "text/markdown"))` + 读取前检查大小上限。

## P2-20 缺少数据出境告知

用户笔记、职业档案、语义搜索的日志摘要、经历生成的近期日报、导入文件的内容，
都会发往用户自行配置的第三方端点。应用内没有任何隐私说明，而个人中心和简历页挂着
「隐私保护」徽章——该徽章实际只表示简历里用了占位符。

收敛为单一自定义端点后这条更需要说明：应用无从保证对端如何处理数据。
