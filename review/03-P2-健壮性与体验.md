**位置**：[WorkLogViewModel.kt:276-327](https://github.com/Hearts-miku/PersonalSecretary/blob/fa9c62c/app/src/main/java/com/example/ui/viewmodel/WorkLogViewModel.kt#L276)

```kotlin
val finalContent = if (refineWithAi) {
    val res = repository.aiRepository.refineImportedContent(content, "工作经历", repository.getSettings())
    res.getOrNull() ?: content          // ← 失败静默退回原文
```

`importCareerProfile` 三个方法都是这个写法。

与 P2-2 同类：把失败包装成成功文案。建议失败时明确告知并让用户选择是否仍以原文导入。

### 🆕 N-8 三个 `cancelEditing*` 是死代码，编辑态没有取消出口

### 🆕 N-11 `_isProcessingAI` 被导入流程误清

**位置**：[WorkLogViewModel.kt:277](https://github.com/Hearts-miku/PersonalSecretary/blob/fa9c62c/app/src/main/java/com/example/ui/viewmodel/WorkLogViewModel.kt#L277)

```kotlin
_isProcessingAI.value = refineWithAi
```

选「直接导入」时 `refineWithAi = false`，这行会把**全局** AI 处理标志置为 false。若此时
有日志总结正在运行，进度条会提前消失、被禁用的按钮会提前解禁，用户可能重复触发。

`finally` 块里的 `_isProcessingAI.value = false` 同理。

**建议**：导入流程用独立的状态标志，或只在 `refineWithAi == true` 时接管全局标志。

### 🆕 N-12 手动保存会产生空的版本备份

**位置**：[WorkLogRepository.kt:407-441](https://github.com/Hearts-miku/PersonalSecretary/blob/fa9c62c/app/src/main/java/com/example/data/repository/WorkLogRepository.kt#L407)

`updateWorkExperiencesManually` / `updateProjectExperiencesManually` 无条件把
`current.workExperiences` 存为「手动保存前备份」。首次编辑时该值为空字符串，于是版本
历史里会多出一条内容为空的记录。

`updateCareerProfileManually` 也是同样的写法。建议加 `isNotBlank()` 判断。
