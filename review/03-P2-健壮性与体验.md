新 token 在取消旧任务之前递增。旧任务的 finally 看到 token 不匹配，不再执行自己的 statusSetter(false)。新任务只切换它自己的状态。例如报告正在运行，用户改为生成简历：报告标志保持 true，简历结束仅把简历标志清为 false。回到报告页，仍显示生成中或禁用生成按钮。不同任务间切换不需要真正同时写入即可触发。

旧的 !isCompleted + NonCancellable join 链改进是有效方向，不能退回无条件旧任务收尾，否则会重新覆盖同类型新任务状态。建议在确认旧任务已结束且新任务尚未置忙时，清理旧任务拥有的状态；或统一保存单一活动任务类型/ID。

验收报告→简历、简历→报告、导入→搜索及连续三次替换；最终所有非活动任务状态均 false。新增快速替换测试使用 runBlocking + delay，并不保证 Android 主调度器推进，不能替代可控生命周期测试。

## N-37 ID 方案仅保护非空快照，无待处理项时仍按内容删除

正常捕获到 ID 的批次现在只删除这些 ID，跨批次同文/多行问题得到改善。但当 pendingIds 为空，仍以完整历史 snapshotRawNotes 调 removeRawNotesForDate。

可达场景：A 已成功总结，临时队列为空，Room 仍保留 A；再次点击整理，捕获空 ID；AI 等待期间新增相同 A；清理时回退按历史 A 删除新 A。还有只剩摘要、rawNotes 为空的场景，可能按日期删除后来的新记录。Room 原文仍保留，不按完整事实丢失列 P1。
