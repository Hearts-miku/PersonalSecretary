# P3 — 低优先级与发布限制

不再把文件重命名、缺少格式化或依赖版本年龄当作阻断缺陷。

- Gradle wrapper 与 schema 7.json 已提交，fix_type.py 和 ExampleUnitTest.kt 已删除；旧报告中的对应待办关闭。
- 报告界面有少量布局与文案问题（如“快捷快捷周期”、四类 chip 使用不滚动 Row）；未经设备窄屏验证，不升级为确定的功能缺陷。
- resume_style 的保存仍是同步文件操作，并吞掉写入异常；可与文件 IO 错误处理统一。
- CryptoManager 已实现 Keystore AES-GCM，但无法取得密钥或加密失败时仍回退 v1 Base64。已有 JVM 往返测试明确允许 v1，不能证明设备上使用了 v2。发布前决定是否允许静默降级，并在设备上验证。
- manifest 明确允许 HTTP；现阶段是自定义端点兼容选择。正式发布应提示明文传输风险或限定允许的地址。
- namespace、release 压缩和依赖清理按发布计划处理，不把“没有开启混淆”直接视为数据泄漏证明。

沿用“尚未发布”的前提：schema 迁移、备份恢复和正式密钥策略列入发布验收，而非重复报告开发期重置为新缺陷。
