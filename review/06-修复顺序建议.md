# 修复顺序建议

> **流程提醒**：七轮里发生过三次回归（详见 [07](07-已修复与回归记录.md)）。
> 最近一次是 4 个编译错误——**一次 `assembleDebug` 就能全部拦下**。
> 动手前 `git fetch && git rebase origin/main`，改完先构建，再提交。

---

## 批次 1 — 构建一次 ⚠️ 仍是最高优先级

从第 4 轮悬置至今。`app/schemas/6.json` 依然缺失，而 `fallbackToDestructiveMigration`
早已移除——迁移一旦有误，全体存量用户启动即崩溃，只能卸载重装。

1. 补一个匹配 AGP 9.1.1 的 Gradle wrapper
2. `gradle :app:assembleDebug` —— 确认能构建
3. 提交自动生成的 `app/schemas/6.json`
4. 在真实的 v5 数据库上跑一次升级，验证 [P1-15](02-P1-功能与安全.md)

**验收**：APK 能装、老库能升、`6.json` 已入库。

补 wrapper 一举三得：解决 `6.json` 缺失、让 [P1-15](02-P1-功能与安全.md) 可验证、
让后续每轮都能在提交前自查——事件 3 那类问题就不会再发生。

在这一批完成前，所有结论仍建立在静态阅读之上。

## 批次 5 — 真加密

[P1-4](02-P1-功能与安全.md)：`CryptoManager` 改用 `EncryptedSharedPreferences` 或
Keystore + AES/GCM。

现有的 `v1:` 前缀机制可以直接复用——真加密时改用 `v2:`，存量 `v1:` 数据仍能正确读出。
这个设计当初就是为迁移预留的，现在正好用上。

同时考虑 `apiKeyText` 不用 `rememberSaveable`，避免明文 Key 进入 saved instance state。
