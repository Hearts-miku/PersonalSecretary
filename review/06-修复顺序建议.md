# 修复顺序建议

> **流程提醒**：九轮里发生过四次回归（详见 [07](07-已修复与回归记录.md)）。
> **Gradle wrapper 已提交，`./gradlew :app:assembleDebug` 现在随时可跑**——

## 批次 1 — 恢复 schema 导出（现在做，成本最低）

[P0-6 回归](02-P1-功能与安全.md) 的两半要分开处理：

| 内容 | 何时做 |
|---|---|
| `exportSchema = false` → `true`，生成并提交 `7.json`，删除失效的 `5.json` / `6.json` | **现在** |
| `fallbackToDestructiveMigration()` → 显式 `Migration` | **发布前** |

理由：schema 历史只能在对应版本存在的当下由 Room 生成。每多发布一个没有 json 的版本，
将来写迁移就多一分手工重建的代价。而破坏性迁移在未发布阶段是合理取舍，不必现在撤销。

顺带把 `fallbackToDestructiveMigration()` 换成带参重载（无参版在 Room 2.7 已废弃）。

**验收**：`app/schemas/` 下只有 `7.json`，内容与实体定义一致。

## 批次 2 — 补测试（阻碍已清除）

wrapper 就位后这批终于可以动手了。[07](07-已修复与回归记录.md) 第四节列了 7 组目标，
前两组直接对应本轮新落地的安全能力：

1. **`CryptoManager` 往返** —— encode/decode 一致性、`v1:` 与无前缀明文的向下兼容。
   注意 JVM 单测里 Keystore 不可用，实际验证的是 `v1:` 降级路径；`v2:` 需要
   instrumented test
2. **配置缺失时不发请求** —— Base URL / API Key / 模型名任一为空都应提前失败并返回可读原因
3. `extractJsonSubstring` 的边界（曾在事件 1 中被回退过）

**验收**：`./gradlew :app:testDebugUnitTest` 通过，且手动改坏任一被测行为时对应测试会红。
