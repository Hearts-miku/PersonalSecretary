## N-29 中文报告文件名归一化冲突，自动保存覆盖已有报告

位置：[MarkdownFileManager.kt:84](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/markdown/MarkdownFileManager.kt#L84)；调用方 [WorkLogViewModel.kt:378](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/ui/viewmodel/WorkLogViewModel.kt#L378)。
**证据：直接运行编译后的生产类复现。**

writeReport 把所有非 ASCII 字母、数字、下划线、短横线和点替换为下划线，并直接 writeText 覆盖。相同区间的默认周报和月报：

```text
2026-10-01_至_2026-10-07_周报.md
2026-10-01_至_2026-10-07_月报.md
→ 两者都是 2026-10-01___2026-10-07___.md
```

探针先保存 WEEKLY，再保存 MONTHLY；报告文件数为 1；读取周报返回 MONTHLY。中文自定义标题也会发生同类冲突。用户无需手动输入重名，默认自动保存即可触发。

建议：展示标题与存储 ID 分离，类型使用稳定唯一标识；保留合法 Unicode 或使用不可碰撞 ID。覆盖已有文件必须有明确策略或确认。

验收：同一区间四类报告分别保存，逐一读取仍各自一致；两个不同中文自定义标题不得覆盖。

## N-30 清空数据后缓存的子目录消失，同进程后续写入失败

位置：[MarkdownFileManager.kt:195](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/markdown/MarkdownFileManager.kt#L195)；目录初始化 [MarkdownFileManager.kt:21](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/markdown/MarkdownFileManager.kt#L21)、[MarkdownFileManager.kt:78](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/markdown/MarkdownFileManager.kt#L78)。
**证据：直接运行编译后的生产类复现，四种写入均失败。**

worklogsDir、tempDir、userDir、reportsDir 都由 lazy 缓存，mkdirs 仅在第一次求值时执行。clearAllData 递归删除整个根目录，只重新创建根目录。已经求值的 File 不会再运行初始化。

探针先访问各子目录，清空后重新写原始笔记、工作经历、日报、报告，均抛 FileNotFoundException。真实启动时恢复逻辑及 loadSavedReports 已会访问多种子目录，因此正常使用很容易命中。许多 ViewModel 保存操作没有 catch，异常还可能终止界面进程；真机崩溃本轮未验证。

建议：每次写入前确保 parentFile 存在，或仅清空内容并保留目录结构。检查删除返回值；统一把 IO 失败转为可见错误。

验收：同一个 Repository 实例清空后立即新增笔记、保存经历、保存报告，全流程成功，无需重启。

## N-37 总结期间补录的笔记可能被旧快照覆盖

位置：[WorkLogRepository.kt:148](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/repository/WorkLogRepository.kt#L148)、[WorkLogRepository.kt:177](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/repository/WorkLogRepository.kt#L177)、[WorkLogRepository.kt:250](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/data/repository/WorkLogRepository.kt#L250)；[HomeScreen.kt:335](https://github.com/Hearts-miku/PersonalSecretary/blob/e30eab9db146a42f9a1b971614c5b52fb89ca005/app/src/main/java/com/example/ui/screens/HomeScreen.kt#L335)。
**证据：静态调用链与可达交互；未进行并发真机复现。**

总结先读取 logEntity/rawContent，再等待网络。此时 Home 的提交按钮只检查输入非空，允许 addRawNote 追加笔记 B。AI 返回后 insertOrUpdate 用调用前的 rawContent A 整行 REPLACE，把 A+B 改回 A，同时标记 isSummarized=true；最后按日期删除临时文件，B 的磁盘副本也被删。

NonCancellable 仅防止取消，不能防止并发写入，也没有检查 updatedAt。即使 B 在摘要写库之后、清理之前写入，按日期清理仍可能删除未处理的临时笔记。

建议：提交摘要时核对记录版本；有新输入时保留它并保持未总结状态。清理只针对已处理的记录片段，或用明确的输入 ID。也可对同日期相关操作加锁，但不能仅把网络后的写入放进 NonCancellable。

验收：用可控延迟的假 AI 在读取后插入 B，完成总结后 B 仍可见且仍待处理，文件与数据库一致。
