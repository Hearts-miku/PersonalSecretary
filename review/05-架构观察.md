# 架构观察

跨文件的结构性问题，不是逐条 bug。

---

## 1. 双写缺少事务性 —— 暴露面连续两轮扩大

首轮就记录的结构性问题：`triggerAISummarize` 的四步双写之间没有原子性保障。

| 轮次 | 暴露面 |
|---|---|
| 第 1~9 轮 | 仅在进程被杀时可能触发 |
| 第 10 轮 | 引入 `activeAiJob` 主动取消，**用户日常切换任务即可打断** |
| 第 11 轮 | 引入批量整理，**一次操作连续执行 N 条管线**，可被打断的窗口成倍增加 |

问题本身没有变，每一轮新功能都在扩大它的触达范围。这是当前最值得优先收口的结构性问题。

**收口方向**：Room 侧多次写入包进 `@Transaction`；文件与数据库写入之间的关键区段用
`withContext(NonCancellable)`；循环式批量任务的标志复位放进 `finally`。

---

## 2. 「用户原文」的边界开始模糊

护栏 prompt 的反幻觉约束以 `<user_raw_content>` 为锚点：模型只能依据这里的内容。
这个约束成立的前提是——**标签里装的确实是用户写的东西**。

本轮 [N-24](03-P2-健壮性与体验.md) 让 `rawNotes` 字段可能装着上一轮的 AI 总结，
随后它又被当作用户原文送回模型。标签隔离在技术上依然零例外，但标签里内容的**来源**不再可信。

建议把「数据来源」作为一条显式约定：`rawNotes` 只存用户输入；AI 产物只进
`summaryMarkdown` 与各类经历字段。

---

## 3. 同一逻辑的多份实现

本轮出现了三处「同一件事写了两遍」：

| 重复 | 后果 |
|---|---|
| URL 规范化：`testConnection` 与 `getEffectiveBaseUrl` | 已经分叉，见 [N-23](03-P2-健壮性与体验.md) |
| 配置校验：ViewModel 与 AiRepository 各一份 | 暂未分叉，见 N-28 |
| 筛选 / 日期钳制：生产代码与测试各一份 | 测试不锁住生产行为，见 [N-25](03-P2-健壮性与体验.md) |

第一处已经造成了实际缺陷，这正是重复实现最常见的走向。

---

## 4. 双写存储的恢复覆盖

| 数据 | 磁盘副本 | 破坏性迁移后可恢复 |
|---|---|---|
| 日报 / 职业档案 / 工作经历 / 项目经历 / 简历 | ✅ | ✅ |
| **待办** | 无 | ❌ |
| **经历版本快照** | 无 | ❌ |

本轮待办的价值上升了（按项目聚合、附带子项列表），而它仍无磁盘副本。

`extractJsonSubstring` 边界、`CryptoManager` 的 `v2:` 路径（需 instrumented test）。

## 6. 分层依然干净

`Composable → ViewModel → Repository → {Room, Markdown, AI}` 无反向依赖；
连接测试也遵循了 ViewModel → Repository → AiRepository 的调用链；加解密边界保持收口。
