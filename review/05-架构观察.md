# 架构观察

## 报告数据应与报告元信息一起保存

现在生成结果只是一个字符串，文件名承担标题、日期、类型三种角色；文件名过滤又抹掉中文区别。因此 N-29 与 N-38 同源。建议引入最小报告记录（ID、区间、类型、显示标题、内容），无须为此重构整个应用。

## 文件与数据库是两份部分重叠的数据

Markdown 包含摘要、经历和报告，但缺少待办与版本历史；Room 含结构化记录，却不存报告。二者不能互相完整替代。旧报告“Room 可以从 Markdown 完整重建”的表述撤销。

NonCancellable 只改变协程取消行为；Room @Transaction 只覆盖数据库操作。两者都不能使普通 writeText 与数据库组成原子事务，亦不能保护网络前读取的快照免受并发修改。N-37 需要版本或写入串行化方案。

## 清空是一次数据生命周期切换

clearAllData 同时影响磁盘目录、Room、缓存状态和正在运行的任务。当前仅覆盖删除本身，因而产生 N-30、N-36。应定义清空后可以立即继续工作的不变量，并集中验证，而不是逐个页面补 reset。

## 测试应覆盖失败与操作顺序

22 个现有测试全部通过，说明它们覆盖的校验、过滤、基础 Diff、消毒及编码兼容行为正常。新增报告和重置操作未被覆盖。生产类探针在相同构建产物上复现两项 P1，显示“编译通过”和“已有测试通过”仍不能替代新功能验收。

本轮按 code-review-skill 的边界、并发和错误路径检查组织审查；未因技能要求修改产品代码。
