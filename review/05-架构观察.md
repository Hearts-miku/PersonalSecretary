## 2. 提示词隔离约定已收口（尚差一处）

三层设计——输入消毒 → 标签隔离 → 系统护栏提示词——本轮完成了关键一步：
`sanitizeUserInput` 增加 `tagName` 参数，转义随标签名走。

```kotlin
fun sanitizeUserInput(input: String, maxLength: Int = 30000, tagName: String = "user_raw_content"): String {
    ...
    .replace("<$tagName>", "&lt;$tagName&gt;")
    .replace("</$tagName>", "&lt;/$tagName&gt;")
}
```

这解决了第 5 轮 `refineImportedContent` 自造 `<imported_data>` 标签留下的缺口——**而且是
真解决**，不只是让调用编译通过。9 处调用的标签配对已逐条核对，全部一致。

**唯一剩下的缺口**是语义搜索（[P1-16](02-P1-功能与安全.md)）：它把日志内容裸拼进 prompt，
既没消毒也没有标签。8 个 AI 功能里 7 个遵循约定、1 个不遵循——补上之后这条约定就是零例外。

## 3. 「失败被包装成成功」已统一收口

这个模式曾以三种形式出现，本轮一次性解决：

| 编号 | 原表现 | 现状 |
|---|---|---|
| P2-2 | JSON 解析失败 → 播报「评估完毕（无须调整）」 | `mapCatching` + `⚠️ AI 未能处理职业履历评估，已跳过` |
| P2-9 | 搜索 AI 失败 → 显示「未找到匹配」 | 回调 `⚠️ AI 搜索未能处理，已降级为本地关键字搜索` |
| N-7 | 提炼失败 → 播报「已由 AI 提炼并导入！」 | 明确报错并中止导入 |

三处统一用 `⚠️` 前缀表达降级，这正是上一轮指出的「缺失的约定」。**新增 AI 功能时应照此
办理**：失败后若选择降级，必须让用户知道发生了降级。

## 4. 仓库层的调度器约定零例外

所有 repository 函数均为 `suspend` + `withContext(Dispatchers.IO)`。本轮把
`getMarkdownDirectoryInfo()` 也纳入（此前是 UI 层直接调 `markdownManager` 绕过 Repository），
UI 层最后一处主线程文件 IO 消除。

---

## 5. 错误处理仍是全局静默降级（但在好转）

全项目只有一处 `Log` 调用，位于零调用的 `AutoSummaryScheduler` 中。三个 JSON 解析函数
（除 `parseCareerUpdateFromJson` 外）、`MarkdownFileManager` 的全部 File IO 仍无日志与异常处理。

但方向是对的：本轮 `parseCareerUpdateFromJson` 去掉了 try/catch 改用 `mapCatching`，让失败
向上传播而非就地吞掉——这个做法值得推广到 `parseTodosFromJson` 与 `parseSearchResultsFromJson`。

---

## 6. 测试覆盖与改动速度的差距在扩大

当前唯一的测试是
[`AISafetyManagerTest`](https://github.com/Hearts-miku/PersonalSecretary/blob/47d4f26/app/src/test/java/com/example/AISafetyManagerTest.kt)（3 条用例）。

七轮里发生过**三次回归**：

| 轮次 | 事件 |
|---|---|
| 第 2 轮 | 回退 8 项已修复的问题（陈旧副本覆盖） |
| 第 4 轮 | P1-13 回归（修 N-2 时改回了旧写法） |
| 第 6 轮 | 4 处「改了一侧没改另一侧」导致编译失败 |

三次都是在没有任何断言拦截的情况下进入 main 的。第三次尤其说明问题——**四个编译错误
本可以被一次 `assembleDebug` 全部拦下**，而它们却是靠人工审计发现的。

改动速度不慢，验证手段却停留在滞后的人工审计上。这是当前最需要补的结构性缺口，
也是 [06-修复顺序建议](06-修复顺序建议.md) 把「构建一次」排在批次 1 的原因。

## 7. 分层依然干净

`Composable → ViewModel → Repository → {Room, Markdown, AI}` 无反向依赖；`Result<T>` 在 AI
边界使用一致；编辑态走 ViewModel；`testTag` 覆盖主要交互控件。

本轮 `_isImportingFile` 与 `_isProcessingAI` 分离、`mdInfo` 收进 ViewModel，都是符合分层
意图的改动。修复应在现有结构内进行。
