# 架构观察

本轮依代码审计技能重点检查了 Kotlin 协程取消、状态归属和数据一致性，未修改源码。

## 原始事实与待处理队列必须分开

本次 rawNotes 从事实历史变成“剩余待总结文本”，但 triggerAISummarize 仍按旧的完整事实模型运行。这个语义变化使串行补录也能丢历史。原始笔记应有稳定 ID，摘要和已处理范围是派生数据。

## 取消不是完成，更不是写入互斥

Call.cancel 接线是进步；Job.cancel 返回不代表 NonCancellable 提交退出。新任务、普通保存和清空共享存储，却没有统一提交边界。建议任务持有明确身份，清空有代际/写入屏障，状态更新仅由当前任务拥有者执行。

## Markdown 与数据库双写

业务数据库应明确为事实来源，Markdown 可作为可重建视图；若两者均可写，需要恢复协议。不能把分开的文件写入和 Room REPLACE 标成原子操作，也不能用字符串包含关系识别已处理记录。

## 测试层级

文件工具测试覆盖局部路径，不能替代 Repository 的两轮总结、并发提交和清空交错测试。当前 AiRepository/Database 直接在 Repository 内构造，建议后续支持注入可控假 AI 与临时数据库，以可重复测试验证时序。
